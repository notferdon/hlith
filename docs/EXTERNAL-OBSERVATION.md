# Recorded external repository observation

On a recorded external Python repository (not included in this archive), an agent was instructed to remove a validation guard that rejected non-positive timeout values. The documented exception contract was unchanged. All 123 reaching repository tests passed before and after the edit. `hlith check --uncommitted --json` refused the change (`exit_status` `10`, `REFUTED`) with a concrete zero-input witness: the original raised the documented exception and the changed version returned zero, taking 76.08 s cold / 74.1 s warm on the optimized build recorded then (effect-account phase 13.98 s; ~1.93 GiB cgroup peak, no swap). A later integrated candidate check on the same anchor took 48.80 s (child max RSS 730200 KiB; MemoryMax=2G, no swap). Both are observations, not a speed guarantee. Before the optimization the same anchor took 807–1476 s across six runs; that historical range is retained as evidence. On that optimized build, standalone `hlith replay` took 6.9 s (`REPRODUCED`), `--pytest-out ... --expect pre` took 5.8 s (`pytest_export.status: written`), and the exported guard test passed on the original code (1.5 s) and failed on the changed code (2.5 s) with no Hlith import. On an earlier build measured before the versioned witness record, the exported test took about 0.2 s on the post tree and failed on the pre tree; that recorded witness is now legacy and no longer exports. These are different builds and scopes, not one timing series. Because that change was requested, it is a contract-change observation, not an accidental regression. This record does not support a claim about accidental regressions.
